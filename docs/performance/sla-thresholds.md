# SLA thresholds for AprilHub BFF

## Endpoint response‑time SLA

| Endpoint | p95 | p99 |
|----------|-----|-----|
| `/v1/me` | < 200 ms | < 500 ms |
| `/v1/profiles/list` | < 500 ms | < 1 s |
| `/v1/entity-types/list` | < 500 ms | < 1 s |
| SSE `/sse` | connection < 100 ms, message < 200 ms |

## System‑wide SLA

- **Error rate**: < 1 % for all endpoints combined.
- **Throughput**: > 100 req/s per BFF instance (rate limiting applies).
- **Availability**: 99.9 % uptime (SLO) over the last 30 days.

## Methodology
The thresholds were derived from production traffic profiles and benchmark runs performed with the existing k6 scripts `run-k6-aprilhub.sh` and `run-k6-aprilhub-extended.sh`.  For each endpoint we collected the 95th and 99th percentile response times from the `hub_bff_http_request_duration_seconds_bucket` histogram, the global error rate from the `hub_bff_http_requests_total{status=~"5.."}` counter, and the throughput from `hub_bff_http_requests_total` counter.

Baseline numbers were compared against existing production metrics to confirm that the thresholds are realistic while still providing meaningful performance guarantees.  The values above represent the minimum performance levels that should be maintained in production.
