# Задача: AprilHub Documentation Refactoring (Этап 021)

## Мета
- **ID / ветка:** `021-aprilhub-documentation-refactoring`
- **Приоритет:** высокий
- **Связанные документы:** `task_list.md`, `docs/AGENT_ARCHITECTURE_CONTEXT.md`, `docs/AGENT_MASTER_PROMPT.md`, `docs/DEPLOYMENT_STRATEGY.md`, `docs/TESTING_STRATEGY.md`, `docs/guides/`, `docs-site/`, `tasks/018-aprilhub-multi-service-documentation-foundation/TASK.md`, `tasks/018-aprilhub-multi-service-documentation-foundation/REPORT.md`

## Цель
Подготовить целостное и актуальное описание AprilHub: что это, для чего нужен и как работает (на уровне людей и на уровне разработки), затем провести системную актуализацию документации с приоритетом полного рефакторинга `docs/` и `docs-site/`.

## Контекст для агента
- Этапы инфраструктуры, интеграций и тестового контура (`001-020`) в основном закрыты; текущий фокус смещается на единый documentation baseline перед следующим этапом развития.
- В проекте уже есть документационный фундамент (`018`), но требуется финальная консолидация, устранение дублирования и улучшение навигации.
- Документация должна одновременно работать для двух аудиторий: человек (общее понимание и ежедневная работа) и агент/разработчик в экосистеме April (архитектурный и операционный контекст).

## Входит в объём
- Подготовить человекопонятный раздел "Что такое AprilHub": назначение, ключевые сценарии, границы системы, high-level flow.
- Описать "Как работает AprilHub" с понятной связкой основных компонентов (`hub-shell`, `hub-bff`, Keycloak, observability, интеграции).
- Описать "Как работать с проектом" для команды: запуск, изменения, проверка, деплой-связки и обязательные ссылки на source-of-truth документы.
- Подготовить агент-ориентированное описание разработки в экосистеме April: ключевые сервисы (в т.ч. Keycloak, Grafana/Loki/Prometheus, Redis/PostgreSQL), правила контекста и ограничения.
- Выполнить рефакторинг структуры документации в `docs/` и `docs-site/`: устранить дубли, выровнять терминологию, обновить устаревшие ссылки и разделы.
- Сформировать карту документации (entrypoints): "с чего начать", "где искать runtime/ops/dev информацию", "какие документы обязательны".
- Обновить task-документацию этапа `021`: `PLAN.md` и `REPORT.md` по факту выполнения.

## Не входит в объём
- Глубокий рефакторинг runtime-кода сервисов, не связанный с документацией.
- Замена зафиксированного технологического стека April без отдельного решения команды.
- Полный ребрендинг UI/маркетинговых материалов вне контекста технической документации.

## Технические ограничения
- Следовать `docs/AGENT_ARCHITECTURE_CONTEXT.md` как источнику истины по стеку и границам платформы.
- Для API-аспектов опираться на OpenAPI/текущие контракты; не создавать альтернативные источники истины.
- Для deploy/dev окружений держать синхронизацию с `docs/DEPLOYMENT_STRATEGY.md`.
- Для тестовых разделов держать синхронизацию с `docs/TESTING_STRATEGY.md`.
- Избегать дублирования между `docs/`, `docs-site/`, ADR и спецификациями: вместо копирования использовать явные перекрёстные ссылки.

## Критерии готовности (acceptance)
- [ ] Есть целостный раздел "Что такое AprilHub" (назначение, ценность, контур системы) в человекопонятном формате.
- [ ] Есть актуальный раздел "Как работает AprilHub" (основные потоки, роли и ключевые сервисы) без противоречий текущей архитектуре.
- [ ] Есть практический раздел "Как работать с AprilHub" для команды (dev-flow, где что менять, как проверять изменения).
- [ ] Есть агент-ориентированный раздел по разработке в экосистеме April (service map, ограничения, обязательные документы).
- [ ] Проведена актуализация `docs/` и `docs-site/`: удалены/помечены устаревшие части, исправлены ссылки, унифицирована терминология.
- [ ] Явно оформлены entrypoints документации для новых участников (human-first + agent-first).
- [ ] По итогам заполнены `PLAN.md` и `REPORT.md` этапа `021` с перечнем обновлённых материалов и открытых follow-up.

## Результат в отчёте
После выполнения оформить `REPORT.md`: какие разделы документации обновлены/перестроены, что стало главным entrypoint для людей и агентов, какие устаревшие материалы убраны или помечены, какие области оставлены в follow-up.
