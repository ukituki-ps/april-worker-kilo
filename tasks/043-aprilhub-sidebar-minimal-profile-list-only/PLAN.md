# План: минималистичный сайдбар AprilHub (только `Профиль — список`)

- **Задача:** [`TASK.md`](./TASK.md)
- **Дата плана:** 2026-04-28
- **Статус плана:** согласован

## Исходные допущения
- Целевой runtime-контракт авторизованной зоны сводится к единственному маршруту `/app/profile/entities`.
- Внешний `profiles-widget` из текущей интеграции (задача 042) остаётся единственным UI для раздела профилей.
- Deep-link на удалённые разделы должен обрабатываться как fallback `not-found`, без краша shell.

## Порядок работ (шаги)
1. Упростить конфигурацию сайдбара и маршрутизацию (`shell-nav-config`, `shell-paths`, `AuthorizedHubContent`).
2. Привести host-контекст и сопутствующие shell-компоненты к новому минимальному контракту.
3. Обновить e2e smoke-набор под новый IA-контур (только профильный список + fallback unknown route).
4. Прогнать проверки (`lint`, `test`, `e2e:smoke`), зафиксировать результаты и ограничения.
5. Сформировать `REPORT.md` по шаблону.

## Риски и откат
- **Риск:** старые e2e-спеки завязаны на удалённые маршруты → **Митигация:** обновить smoke-набор под новый контракт.
- **Риск:** косвенные ссылки на legacy роуты в shell-коде → **Митигация:** типизация + `npm run lint`.
- При необходимости отката: вернуть изменения в `hub-shell/src/shell/*`, `hub-shell/tests/e2e/*`, `hub-shell/package.json`.

## Проверка после выполнения
- Команды (как в `TASK.md`):
  - `npm --prefix hub-shell run lint`
  - `npm --prefix hub-shell run test -- --runInBand`
  - `npm --prefix hub-shell run e2e:smoke`
- Ручная проверка / smoke:
  - в сайдбаре отображается только `Профиль — список`;
  - неизвестный маршрут даёт fallback и кнопку возврата к списку.
