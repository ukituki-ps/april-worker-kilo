## Цель
Сделать **новый** раздел `Профили` в авторизованном shell и подключить его **строго через внешний виджет** (пакет/дистрибутив AprilProfile), без локальных реализаций логики виджета в `hub-shell`.

## Ключевая установка (обязательная)
- Ничего не восстанавливать из предыдущих реализаций задачи 045.
- Не писать "от себя" логику виджета в host-коде.
- Вся бизнес- и runtime-логика виджета должна оставаться на стороне AprilProfile widget.
- Shell отвечает только за: маршрут, встраивание, контрактные входы/выходы и безопасную оболочку.

## Входит в объём
- IA и навигация в `hub-shell`:
  - добавить новый пункт `Профили` в sidebar;
  - настроить целевой маршрут раздела;
  - обеспечить fallback для невалидных путей.
- Интеграция виджета:
  - использовать только внешний `@april/profile-ui` (или согласованный внешний runtime-артефакт);
  - рендерить виджет в разделе `Профили` без локального shim/vendor-клона;
  - передать только контрактные пропсы, которые требуются публичным API виджета.
- Host responsibilities:
  - передать auth/tenant/telemetry контекст в рамках публичного контракта;
  - подключить контрактные callbacks навигации/ошибок без дублирования внутренней логики виджета.
- Проверки:
  - unit/e2e smoke сценарий: логин -> sidebar -> `Профили` -> виджет отрисован.

## Не входит в объём
- Локальные копии виджета в `hub-shell` (`src/vendor/*`), собственные state machine, кастомные fetch/CRUD потоки в host.
- Любая попытка "подменить" внешний виджет временным адаптером с собственной логикой.
- Изменение backend API-контрактов в рамках этой задачи.

## Технические ограничения
- Source of truth — публичный контракт внешнего виджета.
- В `hub-shell` запрещено реализовывать внутренние сценарии виджета (`list/save/details/error orchestration`).
- Обязательна проверка фактически используемой версии внешнего пакета и фиксация в отчёте.
- Ошибки в UI должны быть user-safe; технические идентификаторы идут в логи/observability, если это поддерживает контракт.

## Критерии готовности (acceptance)
- [ ] В sidebar есть новый раздел `Профили`.
- [ ] Маршрут раздела открывается и рендерит внешний widget end-to-end.
- [ ] В коде `hub-shell` нет локального vendor/shim-кода логики виджета.
- [ ] Используется только внешний контракт `@april/profile-ui` (или согласованный внешний артефакт) с зафиксированной версией.
- [ ] Host передает только необходимые контрактные параметры и не дублирует бизнес-логику виджета.
- [ ] Smoke e2e проходит на реальной интеграции.

- Каким внешним способом подключен виджет (пакет/артефакт), какая версия.
- Какие host-точки интеграции изменены (роутинг, wiring, callbacks).
- Подтверждение, что локальная логика виджета в `hub-shell` отсутствует.
- Результаты smoke и оставшиеся риски/release-blockers.
