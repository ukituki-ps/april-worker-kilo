## Исходные допущения
- Scope задачи ограничен архитектурой и документацией; кодовая интеграция SDK/DSN не входит в объём.
- Операционный источник правды по инфраструктурной наблюдаемости остаётся в `infra/observability/`.
- Базовая модель: Sentry для frontend runtime-инцидентов, Loki/Prometheus/Grafana для операционного triage и корреляции.

## Порядок работ (шаги)
1. Зафиксировать архитектурную модель error telemetry в отдельном документе `docs/architecture/`.
2. Синхронизировать интеграционные и host/widget контракты по обязательным полям корреляции и границам ответственности Hub/Profile.
3. Обновить observability index ссылками на новый контур и runbook triage.
4. Добавить runbook triage-инцидентов с цепочкой `Sentry issue -> Loki logs -> Prometheus alert -> root cause`.
5. Подготовить `REPORT.md` с перечнем изменений, рисков и списком зеркальных обновлений для `april-profile-1`.

## Риски и откат
- **Риск:** неявные границы ответственности Hub/Profile для runtime-ошибок. → **Митигация:** отдельный раздел RACI в архитектурном документе.
- **Риск:** drift между `april-worker` и `april-profile-1`. → **Митигация:** явный список mirror-обновлений в `REPORT.md`.
- При необходимости отката: удалить новые разделы/файлы документации в отдельном PR без изменений runtime.
