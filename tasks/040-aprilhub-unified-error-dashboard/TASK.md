## Цель
Собрать полноценный единый Grafana-дэшборд для dev-стенда, который даёт оператору и разработчику быстрый обзор ошибок на всех уровнях (`frontend runtime`, `hub-bff`, `downstream/april-profile`): от общего error-rate и SLI до детализации по сервисам, endpoint-ам, маршрутам и инцидентам с переходом в первичные логи/события.

## Контекст для агента
- В проекте уже зафиксирован observability-контур `Promtail + Loki + Grafana + Prometheus`.
- По предыдущим задачам подготовлен архитектурный и операционный контур error telemetry, включая Sentry-направление для runtime-ошибок.
- На стенде нужен практический инструмент ежедневного мониторинга, чтобы видеть ошибки фронта и бэка в одном месте, а не вручную собирать картину по разным экранам.
- Ключевой сценарий: быстро ответить на вопросы "где горит", "какой слой ломается", "какой сервис/маршрут деградирует", "как перейти к первопричине".

## Входит в объём
- Спроектировать структуру единого Grafana-дэшборда (секции, панели, переменные фильтрации).
- Реализовать/обновить dashboard provisioning артефакты в репозитории (`JSON`/шаблоны/инструкции), чтобы дэшборд разворачивался воспроизводимо.
- Добавить панели верхнего уровня:
  - общий объём ошибок за период,
  - error-rate по слоям (`frontend`, `hub-bff`, `downstream`),
  - распределение по кодам (`4xx/5xx`, runtime/classification).
- Добавить панели детализации:
  - топ проблемных endpoint-ов/роутов,
  - топ сервисов/виджетов по ошибкам,
  - динамика ошибок во времени с выделением всплесков.
- Добавить корреляционные drill-down ссылки:
  - из метрики в Loki-логи,
  - из агрегированных панелей в выборки по `requestId/correlationId/tenant/module/route` (по доступным полям).
- Добавить минимальные operational annotations/памятки на дэшборде:
  - как читать сигналы,
  - какие пороги считаются инцидентом,
  - куда эскалировать при фронт/бэк инцидентах.
- Обновить документацию runbook/observability с инструкцией "как пользоваться дэшбордом" на стенде.

## Не входит в объём
- Полная замена текущего observability-стека и миграция на другой инструмент.
- Production alerting redesign и полная SLO-платформа.
- Реализация новых бизнес endpoint-ов только ради визуализации.
- Коммит реальных секретов/DSN и ручное изменение продовых доступов.

## Технические ограничения
- Использовать существующий стек и источники данных проекта (Grafana/Loki/Prometheus и согласованные telemetry-поля).
- Не ломать текущие dashboards/provisioning; новые изменения должны быть обратно совместимы с dev-стендом.
- Все фильтры и панели должны работать при частичной деградации данных (например, когда часть источников временно недоступна).
- Не допускать утечки PII/секретов в запросах панелей и отображаемых полях.
- Артефакты дэшборда хранить в репозитории в формате, пригодном для версионирования и review.

## Критерии готовности (acceptance)
- [ ] В репозитории добавлен/обновлён единый Grafana-дэшборд ошибок для фронтенда и бэкенда.
- [ ] Дэшборд содержит верхнеуровневые KPI ошибок и детализацию по слоям/сервисам/роутам.
- [ ] Настроены рабочие фильтры (как минимум: период, сервис/слой, environment/stand, route/endpoint при наличии).
- [ ] Из ключевых панелей есть переход к первичным данным (Loki logs/корреляционные выборки).
- [ ] Добавлена документация по использованию дэшборда и базовому triage-инцидента.
- [ ] Smoke-проверка на стенде подтверждает, что панели загружаются и отображают актуальные данные.
- [ ] В `REPORT.md` зафиксированы: ссылка/UID дэшборда, список панелей, проверенные сценарии, ограничения и follow-up.
