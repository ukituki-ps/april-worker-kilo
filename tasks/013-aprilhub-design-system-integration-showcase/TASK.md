# Задача: Design System Integration and Showcase Deployment (Этап 013)

## Мета
- **ID / ветка:** `013-aprilhub-design-system-integration-showcase`
- **Приоритет:** высокий
- **Связанные документы:** `task_list.md`, `docs/AGENT_ARCHITECTURE_CONTEXT.md`, `docs/DEPLOYMENT_STRATEGY.md`, `docs/TESTING_STRATEGY.md`, [`DisignApril`](https://github.com/ukituki-ps/DisignApril.git)

## Цель
Интегрировать дизайн-систему April из репозитория `DisignApril` в проект `april-worker` и развернуть отдельную витрину (showcase) компонентов/токенов, доступную в dev-контуре.

## Контекст для агента
- Текущие UX-этапы требуют опоры на единый источник UI-токенов и компонентных паттернов.
- Дизайн-система ведётся в отдельном репозитории `DisignApril`; интеграция должна быть воспроизводимой и управляемой через версионирование.
- Для следующих этапов (`014`, `015`) необходима рабочая витрина, чтобы сверять реализацию интерфейсов с эталонными компонентами.

## Входит в объём
- Подключить дизайн-систему из `https://github.com/ukituki-ps/DisignApril.git` в проект:
  - определить способ интеграции (package/git dependency/workspace) в рамках текущего репозитория и CI,
  - подключить базовые токены и ключевые UI-компоненты в `hub-shell`.
- Подготовить и развернуть отдельную витрину дизайн-системы:
  - отдельный runtime/entrypoint для showcase,
  - базовые сценарии просмотра токенов/компонентов,
  - доступность витрины в dev-контуре через согласованный ingress/path.
- Обновить документацию по подключению и запуску дизайн-системы/витрины.
- Добавить smoke-проверку доступности витрины и базовой загрузки UI-ассетов.
- Оформить `PLAN.md` и `REPORT.md` по итогам выполнения.

## Не входит в объём
- Полный редизайн всех экранов `hub-shell` в рамках одного этапа.
- Изменение IAM/RBAC-модели, OIDC-протокола и backend-контрактов `hub-bff`.
- Кастомизация Keycloak beyond задач, связанных с потреблением компонентов дизайн-системы.

## Технические ограничения
- Следовать принятому стеку: React + TypeScript + Vite + Keycloak + Nginx ingress.
- Интеграцию дизайн-системы делать без дублирования исходников `DisignApril` в проекте, если это не требуется согласованным процессом.
- Не коммитить секреты, токены доступа и приватные credentials.
- Пользовательский интерфейс (тексты, кнопки, сообщения состояний) реализовывать на русском языке.
- Не нарушать flow deploy/rollback, описанный в `docs/DEPLOYMENT_STRATEGY.md`.

## Критерии готовности (acceptance)
- [ ] Дизайн-система `DisignApril` интегрирована в проект и используется в `hub-shell` минимум в опорных UI-элементах.
- [ ] Отдельная витрина дизайн-системы развернута и доступна в dev-контуре через согласованный URL/path.
- [ ] Документация подключения/запуска витрины и интеграции с проектом обновлена и воспроизводима.
- [ ] Добавлены/обновлены smoke-проверки на доступность витрины и базовую работоспособность.
- [ ] В `REPORT.md` зафиксированы схема интеграции, проверка, ограничения и follow-up.

## Проверка (команды)
```bash
npm --prefix hub-shell run build
npm --prefix hub-shell run test
./scripts/smoke-aprilhub.sh
```

## Результат в отчёте
После выполнения оформить `REPORT.md`: каким способом интегрирована `DisignApril`, где и как развернута витрина, какие проверки проведены и какие доработки перенесены в следующие этапы.
