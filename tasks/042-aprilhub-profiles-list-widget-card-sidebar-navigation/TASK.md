# Задача 042: открыть Profiles list widget-card из сайдбара

## Мета
- **ID / ветка:** `042-aprilhub-profiles-list-widget-card-sidebar-navigation`
- **Приоритет:** обычный
- **Тип:** [интеграция Hub Shell + AprilProfile widget]
- **Связанные документы:**
  - [`task_list.md`](../../task_list.md)
  - [`tasks/041-aprilhub-execute-external-task-040-phase-5-widget-card-layout-modernization-april-profile-1/TASK.md`](../041-aprilhub-execute-external-task-040-phase-5-widget-card-layout-modernization-april-profile-1/TASK.md)
  - [`hub-shell/src/widgets.tsx`](../../hub-shell/src/widgets.tsx)

## Цель
Обеспечить, чтобы при выборе пункта `Профиль-список` в сайдбаре авторизованной зоны AprilHub открывался рабочий `Profiles list` виджет в формате `widget-card` со всей необходимой обвязкой (host-контекст, маршрут, загрузка/ошибки, доступы), соответствующий актуальному интеграционному контракту с `april-profile-1`.

## Контекст для агента
- После документирования phase-5 модернизации карточного layout (`task 041`) требуется зафиксировать реализацию сценария навигации из сайдбара в сам виджет.
- Пункт `Профиль-список` должен вести именно в `widget-card`-представление, а не в устаревший или неполный экран.
- Под "вся необходимая обвязка" понимается полный host-flow: корректный mounting виджета, контекст аутентификации/ролей, обработка состояний загрузки и ошибок, а также эксплуатационная проверяемость через smoke-сценарий.

## Входит в объём
- Проверить и при необходимости доработать маршрут/навигацию для пункта `Профиль-список` в sidebar.
- Гарантировать открытие `Profiles list widget-card` с корректным `HostContext` и параметрами встраивания.
- Подтвердить, что для пользователя с нужными ролями виджет открывается без ручных workaround.
- Привести в актуальное состояние документацию по сценарию (task-story/интеграционные заметки), если фактическое поведение меняется.
- Оформить `REPORT.md` с результатами реализации и проверок.

## Не входит в объём
- Редизайн внутренних карточек профиля, не связанный с входом из sidebar.
- Рефакторинг несвязанных пунктов меню и виджетов.
- Изменения backend-контрактов, если текущих API достаточно для открытия `Profiles list widget-card`.

## Технические ограничения
- Не расходиться с актуальным интеграционным поведением `april-profile-1`.
- Не коммитить секреты, токены, реальные `.env` значения.
- Сохранять существующие паттерны маршрутизации/host-встраивания в `hub-shell`.
- Если обнаружен функциональный разрыв между `hub-shell` и `april-profile-1`, зафиксировать его в отчёте как риск/follow-up без несанкционированного расширения scope.

## Критерии готовности (acceptance)
- [ ] При клике на пункт `Профиль-список` в sidebar открывается `Profiles list widget-card`.
- [ ] Виджет поднимается с полной обвязкой (контекст, роли, загрузка, ошибки) и не требует ручной донастройки.
- [ ] Сценарий подтверждён проверками (локально/смоук), результаты внесены в отчёт.
- [ ] Документация/истории задач обновлены, если в ходе реализации уточнено фактическое поведение.
- [ ] Подготовлен `REPORT.md` по задаче `042` с итогом, рисками и follow-up.
