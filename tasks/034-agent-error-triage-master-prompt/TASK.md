# Задача 034: отдельный агентный промпт для анализа и исправления ошибок UI/API

## Мета
- **ID / ветка:** `034-agent-error-triage-master-prompt`
- **Приоритет:** высокий
- **Связанные документы:**
  - [`docs/AGENT_MASTER_PROMPT.md`](../../docs/AGENT_MASTER_PROMPT.md)
  - [`docs/guides/APRILHUB_AGENT_DEVELOPMENT.md`](../../docs/guides/APRILHUB_AGENT_DEVELOPMENT.md)
  - [`docs/guides/OBSERVABILITY_INDEX.md`](../../docs/guides/OBSERVABILITY_INDEX.md)
  - результаты задачи `033` (архитектурные правила error telemetry)

## Цель
Подготовить отдельный операционный промпт (по аналогии с `AGENT_MASTER_PROMPT`) для агента, который выполняет цикл "анализ ошибок -> локализация причин -> безопасные исправления -> верификация": для кейсов `400/404/503`, падений React-компонентов, `unhandledrejection` и деградаций интеграции AprilHub <-> AprilProfile.

## Контекст для агента
- Нужен узкоспециализированный "incident/fix prompt", чтобы разные сессии агента одинаково проводили triage и не пропускали корреляцию между frontend/backend.
- Промпт должен быть применим как в `april-worker`, так и во внешнем `april-profile-1` (через адаптацию путей и сервисных границ).

## Входит в объём
- Создать новый документ-промпт (например, `docs/AGENT_ERROR_TRIAGE_PROMPT.md`) со структурой:
  - входные данные инцидента,
  - обязательный сбор контекста (Sentry issue, route, requestId, роль, tenant),
  - алгоритм проверки (frontend -> BFF -> downstream -> infra),
  - правила исправления и anti-patterns,
  - обязательный формат отчёта.
- Добавить краткий чеклист "что собрать перед фиксом" и "что проверить после фикса".
- Сослаться из `AGENT_MASTER_PROMPT.md`/карт документации на новый специализированный промпт.
- Подготовить внешний follow-up для зеркального промпта в `april-profile-1`.

## Не входит в объём
- Массовая переработка всех существующих агентных документов.
- Автоматический запуск промпта в CI/hook без отдельной задачи.

## Технические ограничения
- Не дублировать существующие правила без добавленной ценности; опираться на ссылки.
- Сохранить совместимость с текущим процессом `TASK.md` -> `PLAN.md` -> `REPORT.md`.
- Не добавлять противоречивые правила относительно `AGENT_ARCHITECTURE_CONTEXT`.

## Критерии готовности (acceptance)
- [ ] Создан отдельный промпт для incident triage/fix в `docs/`.
- [ ] В промпте зафиксирован обязательный flow корреляции `Sentry <-> Loki <-> Prometheus`.
- [ ] Обновлены ссылки в навигационных agent-документах.
- [ ] Подготовлена внешняя постановка/заметка для зеркалирования в `april-profile-1`.
- [ ] Создан `REPORT.md` с примерами применения промпта.
