# План: интеграция внешнего `profiles-widget` в сайдбар AprilHub

- **Задача:** [`TASK.md`](./TASK.md)
- **Дата плана:** 2026-04-28
- **Статус плана:** черновик

## Исходные допущения
- Внешний виджет доступен из пакета `@april/profile-ui` и экспортируется как `ProfilesWidget` (с alias `ProfilesListWidget`).
- Маршрут `#/app/profile/entities` и пункт навигации `Профиль — список` уже существуют; требуется заменить только runtime-рендер.
- Scope ограничен разделом списка профилей, без рефакторинга остальных профильных экранов.

## Порядок работ (шаги)
1. Добавить подключение `@april/profile-ui` в `hub-shell` и настроить стабильное разрешение импорта для локального рабочего контура.
2. Заменить локальную реализацию `ProfilesListHostWidget` на host-обвязку внешнего `ProfilesWidget` (HostContext, token, BFF base URL, callbacks, error state).
3. Удалить legacy-логику списка профилей из `hub-shell/src/widgets.tsx`.
4. Обновить e2e smoke/интеграционные ожидания для сайдбарного сценария `Профиль — список` с внешним виджетом.
5. Прогнать `lint`, `test`, `e2e:smoke`; зафиксировать результаты и ограничения в `REPORT.md`.

## Риски и откат
- **Риск:** внешний пакет не собран (`dist` отсутствует) в локальном контуре → **Митигация:** alias на исходники пакета для `hub-shell`.
- **Риск:** регрессия e2e, завязанная на legacy-селекторы → **Митигация:** обновить smoke под новый UI и оставить host-level error/assertions.
- При необходимости отката: вернуть `ProfilesListHostWidget` в `hub-shell/src/widgets.tsx` и предыдущие e2e ожидания отдельным revert-коммитом.

  - `npm --prefix hub-shell run test -- --runInBand`
  - `npm --prefix hub-shell run e2e:smoke`
- Ручная smoke-проверка:
  - логин → клик в сайдбаре `Профиль — список` → маршрут `/app/profile/entities` → рендер внешнего `profiles-widget`.
