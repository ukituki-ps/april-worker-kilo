# Задача: Public Guest Landing and Authorized Entrypoint UX (Этап 016)

## Мета
- **ID / ветка:** `016-aprilhub-guest-landing-entrypoint`
- **Приоритет:** высокий
- **Связанные документы:** `task_list.md`, `tasks/000-aprilhub-full-service-roadmap/TASK.md`, `tasks/003-aprilhub-shell-design-system/REPORT.md`, `tasks/012-aprilhub-unified-ingress-auth-hardening/REPORT.md`, `docs/AGENT_ARCHITECTURE_CONTEXT.md`, `docs/TESTING_STRATEGY.md`

## Цель
Собрать полноценный неавторизованный landing в `hub-shell`, который по дизайн-системе объясняет ценность AprilHub, содержит структурированный контент о платформе и даёт понятную, устойчивую точку входа в авторизованную зону через Keycloak flow.

## Контекст для агента
- На этапах `003` и `012` уже сделан базовый UX-контур guest/authorized и унифицирован ingress-path.
- Текущая неавторизованная зона работает как MVP-gate и требует продуктового UX-уровня (контент + визуальная иерархия + CTA).
- Точка входа должна оставаться совместимой с единым ingress и текущим auth-flow (без возврата к прямым портам).
- Этап `016` является базой для последующих задач `014` и `015`.

## Входит в объём
- Спроектировать и реализовать landing-страницу неавторизованной зоны в `hub-shell`:
  - hero/позиционирование продукта,
  - блоки ценности и ключевых сценариев системы,
  - секция навигации в авторизованную зону (primary CTA),
  - базовые состояния загрузки/недоступности auth endpoint (если применимо).
- Привести guest-layout к визуальным и компонентным паттернам дизайн-системы проекта (spacing, typography, colors, buttons, cards).
- Обновить entrypoint логику так, чтобы CTA из лендинга гарантированно запускал корректный login flow через текущий ingress.
- Добавить/обновить UI smoke-проверки неавторизованной зоны и сценария перехода в auth-flow.
- Зафиксировать изменения в `PLAN.md`/`REPORT.md` этапа.

## Не входит в объём
- Кастомизация Keycloak login/account страниц (это scope этапа `014`).
- Редизайн авторизованного layout (header/sidebar/content) beyond минимальной интеграции перехода (это scope этапа `015`).
- Изменение IAM-модели, RBAC-ролей, backend-контрактов `hub-bff`.

## Технические ограничения
- Следовать принятому стеку: React + TypeScript + Vite + Keycloak + Nginx ingress.
- Не менять принятый auth-протокол и source of truth для ролей (Keycloak).
- Не коммитить секреты и real credentials.
- Избегать изменения API/OpenAPI, если этап ограничен только UI/UX и маршрутизацией входа.
- Пользовательский интерфейс (тексты, кнопки, сообщения состояний) реализовывать на русском языке.

## Критерии готовности (acceptance)
- [x] Неавторизованная зона отображает полноценный landing с дизайн-системным оформлением и контентом о системе.
- [x] Primary CTA на landing стабильно переводит пользователя в действующий Keycloak login flow через единый ingress.
- [x] После успешной авторизации пользователь возвращается в авторизованную зону без ручного вмешательства в URL/порты.
- [x] Smoke-проверки guest->login path обновлены и проходят.
- [x] В `REPORT.md` зафиксированы UX-решения, изменённые компоненты, проверки и ограничения/follow-up.

## Проверка (команды)

```bash
./scripts/smoke-aprilhub.sh
```

После выполнения оформить `REPORT.md`: какие блоки лендинга реализованы, как организован вход в auth-flow, какие проверки выполнены и какие UX-доработки перенесены в этапы `014-015`.
